How to document the plan format: three ways, one recommendation

The plan format (smaltdb's plan layer, ADR 0014) is what SQL and smaltdf both build and the engine runs: JSON-safe operations and expressions, versioned on its own. You lean towards treating it as a language. The boards beside this one mock up A and C together.

A · A language (recommended)
Plan language section in the engine's reference: syntax diagrams of the JSON, an entry per operation and expression in the reference shape, a JSON playground.
+ Matches what plans are: the neutral way in, the target every language builds.
+ Same tools and shape as SQL's and smaltdf's reference.
+ Diagrams show which fields an operation takes, at a glance.
− Big: 21 operations and 12 expression kinds, each an entry.
− The format is experimental: pages must say so, and change with it.
B · Code samples
The builder API (plan.scan, plan.filter …) documented as a TypeScript API, with JSON shown only as what planToJSON writes.
+ Small; what TypeScript callers write.
+ Fits today's reference/engine/plans.md.
− Hides the JSON, which is what other languages and tools send.
− No syntax to see; plans read as code, not as a format.
C · The Rosetta view
Plans shown beside SQL and smaltdf for the same query, with the tree view; no reference of its own.
+ Teaches what a plan is fastest.
+ Cheap once the playground exists.
− Not a reference: no complete list of fields.
− Needs smaltql to export the plan of a statement.
The recommendationA, with C as its opening page (one query, every language) and on every SQL and smaltdf playground ("Show the plan"); B stays as the builder API's own entries, on the same pages.
ExperimentalThe plan format is experimental, version 1, until its stability ADR (smaltdb ADR 0014, section 4). Its pages carry a marker that says so, beside the work-in-progress badge.
SQL to plansmaltql has no public way to give a statement's plan (its toPlan is internal). "Show the plan" for SQL needs one, added to smaltql.
The tree viewA text form for reading plans, built on the engine's expression printer (print.ts), which prints expressions today but not whole plans.
