One query, every language, one plan

The page that makes "neutral" visible: the same query written in SQL and in smaltdf, and the plan both of them build, run by the engine to one result. It opens the Plan language section, and every SQL and smaltdf playground gets "Show the plan". smaltdf can give its plan today (frame.plan()); SQL needs smaltql to export the plan of a statement first.

SQL · smaltql
The SQL you know
SELECT region, sum(qty) AS qtyFROM saleWHERE qty > 1GROUP BY region;
Dataframes · smaltdf
TypeScript method chains
table('sale')  .filter(col('qty').gt(1))  .groupBy('region')  .agg(col('qty').sum());
Plan · smaltdb
What both of them build: the tree, and its JSON
aggregate  keys [#0.0]  aggs [sum(#0.1)]
└─ filter  cmp_gt(#0.1, 1)
   └─ scan sale  columns [0, 2]

The tree view

The Plan tab shows the tree. A plan read at a glance: one line per operation, indented under the operation that reads it; expressions in the engine's own short form (#input.index for a column, $n for a parameter, fn(args) for a call), the form smaltdb already prints expressions in. JSON is for writing a plan; the tree is for reading one.
